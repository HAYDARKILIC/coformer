# CoFormer: code, data, tables and figures

This repository accompanies the article *Does a Differentiable Solver Teach Autoformalisation? A Controlled Study of Co-Training through a Relaxed MaxSAT Layer* (H. Kilic, Ostim Technical University; submitted to the *Journal of Artificial Intelligence Research*). It is intended for reviewers and editors.

Repository: <https://github.com/HAYDARKILIC/coformer> It contains the experiment code, every per-run result, the generated data, the analysis scripts, and the tables and figures of the article. The manuscript itself is not included.

The study asks whether routing the gradient of a relaxed MaxSAT layer into the translator of a solver-aided reasoner (co-training) makes its formalisations more faithful. The design covers:
- a 2×2 factorial (bridge × solver gradient);
- an estimator replication (E family) and a partial-supervision study (P family);
- two time-stamped follow-up studies and a harder-language benchmark (family H);
- a 7B natural-language pilot on ProofWriter and FOLIO.

## Quick start: check every reported number (CPU, a few minutes)

```sh
git clone https://github.com/HAYDARKILIC/coformer.git
cd coformer
pip install -r requirements-analysis.txt
./reproduce.sh          # recomputes analysis/*.json, tables/*.tex and figures/*
git status              # shows which outputs changed (see "Expected differences")
```

`reproduce.sh` reads only the stored run files in `results/CoFormer/`. It also verifies the SHA-256 time stamps of the pre-specified follow-up studies (`specs/verify_specs.py`).

## Expected differences after `./reproduce.sh`

- **Tables:** none. The committed tables and the article use the archived final state; for E1 and E2 this is `results/CoFormer/outputs/confirmatory_plan_ii.csv` of the last session (E1: Holm-adjusted p 0.112; E2: p 0.193).

## How the experiment notebook was checked

The notebook was executed headlessly against a copy of `results/CoFormer`, on CPU, with the full-scale preset forced. Three groups of cells were skipped because they need a GPU: the cells that run small equivalence trainings (10h–10j) and the natural-language stage (B, C).

- The fingerprints matched (`RUN_FP 1e08afd74c`, `CODE_FP 65a9991c`).
- Every stored run was resumed rather than retrained.
- 122 of the 126 analysis outputs that the notebook writes to `outputs/` were byte-identical to the archived ones.
- The four that differed contain the run date, the device name, the skipped natural-language stage, and the corrected health-check label.

## Re-running the experiments (GPU)

- **Hardware.** The reported runs used one NVIDIA A100 40 GB on Google Colab Pro+. The notebook selects the full-scale preset only on a GPU with at least 38 GB, and its fingerprint guards refuse to mix results across presets or code revisions.
- **Resuming from the stored results.** Copy `results/CoFormer` to `./CoFormer_run`, or to `MyDrive/CoFormer` on Colab. Every completed run is detected and skipped; only the analysis cells and a few small equivalence checks run.
- **From scratch.** Start with an empty state folder. Measured costs (article, Appendix C):
  - about 13 min (family A) and 21 min (family B) per main-matrix run;
  - 31.4 GPU hours for the second follow-up study;
  - 43.1 GPU hours for family H.
- **Headless.** `python3 scripts/run_headless.py --state-zip <state.zip>` runs the notebook with no interaction.
- **Natural-language stage.** Additionally needs the Hugging Face model `Qwen/Qwen2.5-7B-Instruct` and the pinned versions in `requirements.txt`.

## Pre-specification and its limits

The follow-up studies were specified in machine-readable files before their first run. The notebook e-mailed their SHA-256 hashes to the author at the time:

| Specification | Written (UTC) | SHA-256 |
|---|---|---|
| First follow-up study, `plan_III.json` | 2026-09-26 16:12 | `7eeccd20da40c106…` |
| Second follow-up study, `followup2.json` | 2026-10-01 05:43 | `118c0051d4874c09…` |
| Family H, `followup_h.json` | 2026-10-01 05:43 | `84f249584936c2a0…` |

The family-H text-generator source has SHA-256 `3b1aa78106f00a3c…`.

These are e-mailed time stamps, not public registrations, and the follow-up designs were written after the results that motivated them were known. The planned hypotheses of the main study are fixed in the notebook (Cell 3b) without an external time stamp. The article states these limits.
